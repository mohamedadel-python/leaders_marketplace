Vendor application API contract: the "Sell with us" button

A signed-in customer applies to sell with the account they already have. The button asks the backend for a one-time link. The link signs the same account into the Odoo website and opens the application form, the status of their application or the vendor portal, so the customer never signs in twice. When the application is approved, the same account becomes the vendor owner.

Implemented by backend · tested on a test server · 5 November 2026

Companion to the storefront contract, the auth contract and the storefront content contract. One endpoint is new. No existing endpoint changed shape.

Same conventions as the other contracts: JSON, no envelope, camelCase, optional fields omitted, errors as { code, message } in the language of Accept-Language. CORS as before.

What the button does

  1. Not signed in: send the visitor to your own sign-in or sign-up page (/auth/login, /auth/register), then come back to the button. There is no separate sign-up for vendors: the customer account is the vendor account.
  2. Signed in: call POST /vendor-apply/link with the Bearer token when the button is clicked, and open the returned url in the same tab.
async function sellWithUs() {
  if (!accessToken) return router.push("/login?next=sell");
  const r = await fetch(`${API}/vendor-apply/link`, {
    method: "POST",
    headers: { Authorization: `Bearer ${accessToken}`, "Accept-Language": locale },
  });
  const body = await r.json();
  if (r.status === 401) return refreshThenRetryOrLogin();
  if (!r.ok) return showError(body.message);   // 403 / 429: see the error codes below
  window.location.assign(body.url);            // valid once, for 60 seconds
}

Do not prefetch the link or keep it: it works once and only for 60 seconds. A used or expired link opens the Odoo sign-in page, where the customer can still sign in with the same email and password.

POST/vendor-apply/linkOne-time link for the "Sell with us" buttonBearer

No body. The answer depends on the customer's application, see where each status goes. status also lets you change the button text: "Sell with us", "Follow your application" or "Vendor dashboard". Limit: 10 requests a minute per IP.

// POST /vendor-apply/link
// Authorization: Bearer <accessToken>
// no body

interface VendorApplyLink {
  status: "none" | "pending" | "rejected" | "approved";
  url: string;          // absolute; open it right away, works once within 60 s
  reference?: string;   // the customer's latest application, e.g. "VA-0012"; omitted for "none"
}

Where each status goes

statusThe customerThe link opensSuggested button text
noneNever appliedThe application form. Name and phone come from the account. The email is the account's email and cannot be changed.Sell with us
pendingApplication submitted or under reviewThe status page of that application. No second application can be opened.Follow your application
rejectedLast application refusedThe status page with the reason and an Apply again button. The new form is filled with the old data, and the documents that were not refused are kept.Apply again
approvedApproved vendorThe vendor portal, /my/vendor.Vendor dashboard

To set the button text before the click, call the endpoint when the page loads and use status only. Do not use the url of that call: ask for a new link on the click.

Rules

  • The link works once, within 60 seconds. Ask for it on the click and do not keep it. Opened later, it shows the Odoo sign-in page, where the customer can still sign in with the same email and password.
  • Open it in the same tab with window.location.assign, not in an iframe or a popup.
  • Do not link to /vendor/apply directly. It needs a signed-in customer, so a visitor who opens it without the button sees the Odoo sign-in page.

Odoo pages

These are Odoo website pages, not API endpoints. They are listed so you know where the customer lands.

PageWhat it does
/vendor/apply/start?ticket=…Signs the account in with the ticket and redirects. A used or expired ticket redirects to the Odoo sign-in page.
/vendor/applyThe application form, for a signed-in customer.
/vendor/apply/status/:tokenStatus of one application. Also the link in the confirmation email.
/my/vendorThe vendor portal.

What changed

  • /vendor/apply now needs a signed-in customer. A guest who opens it goes to the Odoo sign-in page first, then back to the form. Use the button flow above rather than linking to /vendor/apply directly.
  • Approval keeps the account. The customer's own account becomes the vendor owner: same email and password, no "set your password" email. The account joins the vendor company, so the customer's own orders and invoices from then on count under that company.
  • Applications filed earlier without an account, and applications created by staff, work as before.

How to verify

TOKEN=$(curl -s -X POST $API/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"customer@example.com","password":"…"}' | jq -r .accessToken)

curl -s -X POST $API/vendor-apply/link -H "Authorization: Bearer $TOKEN"
# {"status":"none","url":"…/vendor/apply/start?ticket=…"}

curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' -c jar "<url>"
# 303 …/vendor/apply          (signed in)
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' "<url>"
# 303 …/web/login?redirect=…  (the link works once)
