## STATE MACHINE (non stored, computed for one customer's checkouts)
Part codes: vendor order pending=placed, confirmed, processing, partially_fulfilled=partially_shipped, fulfilled=shipped, completed=delivered, cancelled; `returned` when every product line is fully returned (received/refunded). Company part: cancel=cancelled; sale/done with outgoing pickings: none done=confirmed (processing when one is assigned), some done=partially_shipped, all done=delivered; no picking: confirmed (delivered if locked done).
Overall: no part=placed; all cancelled=cancelled; some cancelled + others alive=partially_cancelled (`progress` keeps the state of the living parts, used by the timeline); all living returned=returned; all delivered/returned=delivered; all shipped+=shipped; any shipped/partially/delivered=partially_shipped; any processing=processing; any confirmed=confirmed; else placed. Pure function `aggregate_status(codes)` is tested on a table.
## ROUTES_API
- GET `/my/marketplace/checkouts` (+ `/page/<n>`), auth user: params `search` (reference, seller name/store, product name), `status` (one of the codes, unknown=all), `date_begin`/`date_end` (YYYY-MM-DD on order date, inclusive, invalid ignored), `sortby` date|date_asc|total. One row per website sale.order of the customer's commercial partner: states sale/done, or cancel with vendor orders / a customer cancel (drafts, quotations excluded). Total = `_marketplace_checkout_total()` for split checkouts else amount_total. Status filter/total sort are done in Python (status not stored), then paged (10/page) with `portal_pager` (filters kept in links).
- GET `/my/marketplace/checkouts/<sale_order_id>`: unknown/draft = 404, other customer's = 403 AccessError, else header with overall badge, checkout timeline, company section (lines, deliveries with tracking, invoice PDFs `<access_url>?report_type=pdf`, link to the standard sale order page), one section per seller (store link, items, each fulfillment group with timeline + tracking (link when `tracking_url`), vendor invoice/credit-note PDFs `/my/marketplace/vendor-invoices/<id>`), delivery breakdown text (A1) and total, whole-checkout "Cancel entire order" chip.
- POST `/my/marketplace/checkouts/<id>/buy-again` (csrf, same ownership): each product of the company lines and the vendor lines (delivery lines skipped, same product summed) goes through `cart._cart_update(product_id, add_qty)` of `request.website.sale_get_order(force_create=True)`, so current winner offer/price/stock rules apply. Skipped: archived/unpublished/not sellable (UserError of the cart), vendor product without a live offer, out of stock. The customer sees a cart warning (`shop_warning`): "Some items could not be added again: Product (reason), ...". Redirect 303/302 to /shop/cart. Prices are re-validated at checkout by the existing `_leaders_revalidate_marketplace_prices`.

## UAT
1. Settings > Marketplace > enable "Unified My Orders". 2. Customer /my: "My orders" opens /my/marketplace/checkouts. 3. Buy a mixed cart (company + 2 sellers): ONE row with the checkout total, payment method and status; filter by status/date/search seller or product; sort by total. 4. Open it: timeline, company section, one section per seller, invoices, chips (with cancellation enabled: cancel chips until something ships; return chip after delivery). 5. "Buy again": cart holds the products at today's winning offers; change an offer price/unpublish a product first to see the price update and the skipped warning. 6. Turn the setting off: card back to old list, new URLs 404. Check ar and en.
## LIMITATIONS
Company-only orders: no cancel/return/report from this page (A2 forms live on vendor orders); the company section links to the standard sale order page (`/my/orders/<id>`). Company part "returned" is not detected (only vendor returns count). Status filter is computed in Python over the customer's matching checkouts (fine for tens/hundreds). Buy again uses the current winner, not the seller the customer picked before; for a quantity above stock the cart clamps it (not reported as skipped). Delivery breakdown text only exists for split/zone checkouts.
## DECISIONS
Non-stored status; single model method for the state machine so list, detail, timeline and tests share it. `_timeline` also accepts a sale.order (lm_timeline reused). Order page logic for returnable lines/rating moved to model methods (no behaviour change) so chips and page cannot diverge. Cart warning is the standard `shop_warning` (no session flash needed).
