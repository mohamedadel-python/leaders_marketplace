## ROUTES_API
POST /api/v1/shipping/webhook/<code>, header X-Signature (hex HMAC-SHA256 of raw body; optional X-Timestamp => signed text "<ts>.<body>", 5 min). Body (dummy): {"events":[{"id":"e1","awb":"DUM..","status":"picked_up","raw_status":"PU"}]}. Response {"received","applied","ignored","duplicates","unknown"}; 202 if all unknown; 400 bad payload; 401 signature; 404 unknown/inactive/manual provider or setting off; 413 > 1 MB.
POST /my/vendor/fulfillment/<id>/create-shipment (form provider_id); GET /my/vendor/fulfillment/<id>/label (owner only).

## UAT
1. Enable setting; Configuration > Shipping Providers: activate Dummy, Generate secret. 2. Vendor portal order page: pick provider, "Create shipment / label": AWB shown, tracking prefilled, label downloadable. 3. Sign a JSON body with the secret and POST it: picked_up ships, delivered delivers, refused on COD cancels via A3 flow. 4. Replay: duplicates count. 5. Disable setting: 404.

## LIMITATIONS
Webhook needs the JSON raw body (form-encoded bodies not supported). No rate limit on the public webhook. picked_up ignored for FBL (logged, unprocessed). delivered before picked_up is logged, not applied (and a replay is ignored). Groups are matched by AWB or group name only for the same provider. No per-vendor providers.

## DECISIONS
Type dispatch inside the base methods (extensions call super for other types). Carrier acts as base.user_root. `_parse_webhook` receives raw bytes. Event id fallback = hash when carrier gives none.
