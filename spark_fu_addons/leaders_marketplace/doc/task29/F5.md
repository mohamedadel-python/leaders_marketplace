## DECISIONS
- Wrong scope: a checkout WITH vendor orders posted to the new route goes through the same whole-checkout path (`vendor_order_ids[:1].action_customer_cancel(scope="all")`), identical result to A2 (tested).
- Zero vendor orders: same status rules (`_leaders_customer_cancel_all_status`, also used by the vendor-order scope 'all' now), reason validation, `_leaders_cancel_company_part` (draft credit note + draft refund payment, pickings cancelled), no vendor mail.
- The existing customer confirmation template is on leaders.vendor.order, so a new template `mail_template_customer_order_cancelled_by_customer_company` (model sale.order) is used; same event/setting `customer_order_cancelled_by_customer`, via `notify(..., template_xmlid=)`.
- Form shown in the company section only for company-only checkouts (mixed ones keep the D1 chip). Contact support: `/contactus?subject=<order name>` (standard contactus prefills `subject` from request.params), shown when the company part is delivered, plus the reference as text.
## SETTINGS
None new. Uses `customer_can_cancel_orders` (A2), `cancel_window_hours` (from sale date_order), `unified_customer_orders` (D1), notification `customer_order_cancelled_by_customer`.
## ROUTES
POST `/my/marketplace/checkouts/<sale_order_id>/cancel` (auth user, csrf): `reason_id` (mandatory), `note`. Both switches off -> 404; other customer 403; unknown/draft 404. Success: redirect `/my/marketplace/checkouts/<id>?cancelled=all`; refusal: `?error=<msg>` (the detail page now shows the error alert).
Detail page (after cancel): "You cancelled this order" + "Your refund is being processed." (refund draft, not COD) or the COD line; list status = Cancelled.
