## ROUTES_API
No new routes. `/my/vendor/orders` gets a "Ship by" column + red "Late" badge; `/my/vendor/orders/<id>` shows "Ship by: <date> [Late]"; `/my/vendor/performance` shows a "Late shipments" column.

## UAT
1. Settings > Marketplace: "Ship-by SLA" (default 2 days); optionally set a tier's "Ship Within (days)".
2. Confirm a vendor order: backend form shows Ship By; vendor portal list shows the date.
3. Move the deadline into the past (or wait) and run cron "Marketplace: Late shipments": order flagged Late (backend "Late" filter, red badge in the portal); each reviewer gets a to-do activity and the vendor an email (needs the "order late" notification ticked in Settings). A second run does nothing new.
4. Ship the order: Late badge disappears.
5. Performance > Vendor KPIs > Recompute: "Late Shipments" column. Turn on "Flag High Late-Shipment Rates": a draft warning penalty is created above the threshold.

## LIMITATIONS
- `is_late` is true only while the order is unshipped and past due; a late-shipped order stops being "Late" (the KPI keeps that history through date_shipped > ship_by_date). It refreshes hourly (cron), so the badge can lag up to one hour.
- The KPI ignores cancelled orders (any canceller) and orders without ship_by_date (pre-upgrade history); pending orders were already excluded.
- The setting field is an Integer: clearing it to 0 deletes/zeroes the param; 0 disables the deadline for vendors without a tier value (a deleted param reads as default 2).
- No email to the customer.

## DECISIONS
- Data is always stored; the visible notifications sit behind the event switch (off on upgrades), the penalty behind its own setting (off).
- If the event is disabled the cron does not set `late_notified`, so enabling it later notifies orders that are still late.
- Reviewers = group_marketplace_reviewer (as vendor applications).
