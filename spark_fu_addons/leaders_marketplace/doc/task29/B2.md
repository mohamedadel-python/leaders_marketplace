## ROUTES_API
- GET /my/vendor/import : page (templates, upload, history)
- GET /my/vendor/import/template/<new_products|catalog_offers|update>.<xlsx|csv>
- POST /my/vendor/import/upload (csrf; multipart: kind, file, submit_after_import) -> <=200 rows validated synchronously, else by cron; redirects to job page
- GET /my/vendor/import/<id> : counts, error preview, "Confirm import of N valid rows"
- POST /my/vendor/import/<id>/confirm (csrf) -> state confirmed + cron trigger
- GET /my/vendor/import/<id>/errors.<csv|xlsx> : columns row, column, level, message
All: feature off => 404; foreign/unknown job => 404; frozen vendor => 403; same terms/role rule as product creation (`_require_vendor`).

## UAT
1. Settings > Marketplace: tick Vendor Bulk Import. 2. Vendor: Products > Bulk import; download the template; fill; upload. 3. Job page shows counts; download error file; click Confirm. 4. Wait <=5 min (or the cron is triggered at once): status Done, offers appear in Products as Draft (or Pending with "submit after import"). 5. Backend Operations > Vendor Imports shows the job, lines, log.

## LIMITATIONS
- Image download does DNS check then requests resolves again (small DNS-rebinding window); redirects are followed manually up to 3, each re-checked.
- Rows with image URLs are fetched at apply time (not validation), so a bad image is an apply-time warning.
- Update-by-SKU price change does not reset the offer to draft (portal edit form does); it only writes price.
- Max 5000 rows and 10 MB per file. Example rows (SKU starting EXAMPLE-) are skipped. Categories matched by name (or full path) only; one category per product.
- Discount dates are read in the uploader's time zone.

## DECISIONS
- Rules live in one method (`_leaders_check_rules`) called at validation (with in-file counters for duplicates / tier limit) and again per row at apply; apply uses the stored JSON payload, not the file.
- Each row is applied in a savepoint; failures mark the row failed and the batch goes on. Job-level failure only for unreadable file / missing columns / vendor no longer approved. Jobs locked with FOR UPDATE SKIP LOCKED.
- Initial stock for FBL rows is a row error; if a fulfillment policy forces FBL after the fact, the stock is skipped with a warning.
- New products created like vendor_product_create (creation code duplicated in the import; stock/submit shared through offer helpers).
