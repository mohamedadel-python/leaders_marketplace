## ROUTES_API
- GET /my/vendor/finance/statement?date_from=YYYY-MM-DD&date_to=YYYY-MM-DD (owner only; staff 403). Default = current month. Bad dates: page shown with an error and the default period.
- GET /my/vendor/finance/statement.pdf and .xlsx (same params; invalid -> 400 text). PDF is HTML in tests (no wkhtmltopdf), as for other reports.
- GET /leaders/vendor_statement/xlsx?vendor_id=&date_from=&date_to= (backend, manager/finance groups only; used by the wizard).

## UAT
1. Owner: Finance > "Statement of account": pick dates, Show; check opening/closing; Download PDF / XLSX.
2. Staff user opening the URLs gets 403.
3. Backend: Contacts > vendor > Marketplace Vendor tab > Vendor Statement > Print PDF or Download XLSX.

## LIMITATIONS
- Ledger keeps no state history: a line's status is its status now (per-state closing split uses current states).
- Dates are the UTC date of create_date.
- Paid (settled) earnings remain in the ledger balance: the statement is the wallet ledger (lifetime movements), and shows status per line + closing split hold/available/settled; there is no separate payout debit line.
- Settlements listed are those whose period overlaps the statement period (all states, including cancelled), payout account masked (A4).

## DECISIONS
- Basis: all wallet transactions of the commercial vendor, any state, except cod_collected (same as _leaders_check_ledger) so closing (period ending today) == wallet hold+available+settled of the check (tested). Signed amount: credit > 0, debit < 0. Date = create_date (ordering create_date,id); available_date only informational.
- One method feeds portal, PDF, xlsx (xlsxwriter, already shipped), wizard. Max range 366 days.
- Backend xlsx via a small route instead of an attachment (no orphan attachments).
- Report has no binding_model: it needs dates, so it is reached through the wizard.
