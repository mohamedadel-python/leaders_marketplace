## UAT
1. Enable Settings > Marketplace > Customer Order Cancellation (optionally window hours).
2. Customer buys a mixed cart (company + 2 vendors) paid online, opens the order from Marketplace Purchases: both buttons visible with a reason drop-down and note.
3. "Cancel order" with a reason: every vendor order and the company sales order are cancelled, deliveries cancelled (reservations released), each online-paid vendor order gets a draft outbound refund payment (Accounting tab), the company sale order gets a draft credit note (if invoiced) + draft refund payment (sale order form "Cancellation" group). Finance posts credit note first, then the refund payment (it reconciles automatically).
4. "Cancel this seller's part": only that vendor order is cancelled.
5. COD order: cancel works, no payment/refund created; `cancelled_by_type=customer`, `payment_method=cod`.
6. Ship any group of the scope: the buttons vanish and "Request a return after delivery" shows; POST is refused.
7. Emails: customer confirmation and vendor "do not ship" mail queued (only if the two new notifications are ticked; upgraded DBs start unticked).
8. Performance > Vendor KPIs > Recompute: customer cancellations no longer count in orders or cancellation rate.

## LIMITATIONS
- Whole-checkout cancel needs every vendor order and the company part unshipped ("any group shipped" refuses the whole); the seller part button stays available for unshipped sellers.
- Company part: a shipped (done) picking blocks it. A posted invoice is not cancelled: a DRAFT credit note is prepared (finance posts it). The refund payment amount is the paid part of the invoice (or the company sale order total when paid by transaction without invoice). Nothing is auto-posted.
- The button is on the vendor order page only (the company order alone, when the customer has no vendor order, is not reachable from the portal).
- If a vendor already cancelled this vendor order, the page shows no cancel form for it (the other parts must be cancelled from their own pages).
- `applies_to = vendor` is stored but the vendor cancel form still takes free text (no reason list yet).

## DECISIONS
- A customer cancel calls the same `action_cancel` (sudo) as backend/vendor; it stores type customer first and uses context `leaders_customer_cancel` to skip the generic "order cancelled" email (customer gets one dedicated confirmation instead of one per vendor order; vendors get one each).
- KPI exclusion: the customer-cancelled orders are removed from the whole KPI set (order count, completion and cancellation rates); rows with no type (pre-A2) count as before. Penalty auto-warning reads the snapshots so it inherits this.
- For A3 (COD refusal counter): a customer cancel is `state=cancelled, cancelled_by_type='customer'` (any payment_method incl. cod) and happens only before shipping; a COD refusal at the door is a different, post-shipping event and must not count `cancelled_by_type='customer'` orders.
- Buy Box refreshed via `_recompute_buybox_winner` for the cancelled vendor lines' products.
