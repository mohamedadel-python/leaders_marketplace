## SETTINGS

- `leaders_marketplace.allow_vendor_attributes` default False: on => vendors may add new values to existing attributes and create new attributes (create_variant always; or no_variant for "Specification"). They are global (all vendors see them).
- `leaders_marketplace.vendor_max_extra_images` default 8 (0/empty = 8).

## MODELS_FIELDS_MIGRATIONS
New field `product.template.leaders_specs` (Text, translate). No new models, no ACL changes, no migration.

## ROUTES_API
- POST /my/vendor/products/new and /<offer_id>/edit: with the hidden `lm_variants_form=1`, also read `attr_values_<attr_id>` (repeated), `new_values_<attr_id>` (comma list), `new_attr_name/new_attr_values/new_attr_kind` (variant|spec), `extra_images` (multiple files), `remove_image_ids` (repeated), `leaders_specs`. Create: if the selection yields >1 variant no offer is created; redirect to the variants page (prefilled from `sku`, `price`, `fulfillment_type`, `currency_id`, `markets` query params). Otherwise the classic single offer.
- GET/POST /my/vendor/templates/<tmpl_id>/variants: table of the vendor's offers and of "variants without offer"; POST fields fulfillment_type, currency_id, market_ids, and per variant `create_<pid>`, `sku_<pid>`, `price_<pid>`, `stock_<pid>`, `discount_<pid>` (percent, needs vendor_discounts_enabled). All rows validated first; one draft offer per ticked row created atomically (savepoint).
- POST /my/vendor/templates/<tmpl_id>/submit: sends every draft/rejected offer of the vendor on that template through `_leaders_vendor_submit`.
Feature off => 404; foreign/shared/unstamped template => 403.

## UAT
1. Settings > Marketplace: tick "Vendor Variants, Images and Specifications" (optionally "Vendors May Create Attributes", set extra images).
2. Vendor > Products > Add Product: fill name/SKU/price (base values), tick Size S,M and Color Red, add extra images and specs lines, Save. The variants page lists 2 variants with SKUs prefilled; edit SKU/price/stock (/discount), Create offers; then Submit all draft offers.
3. Backend: Marketplace review approves the product; website product page shows the gallery images, the variant picker and a Specifications table.
4. Vendor edit page: add value L to Size -> "Variants without an offer" shows L; try removing S with offers -> refused.

## LIMITATIONS
- Only attributes with create_variant 'always' (variant axes) and 'no_variant' (specs) are offered; 'dynamic' ones are not (dynamic variants do not exist until purchased, so no offer per variant is possible).
- Adding a new option (attribute line), or removing values/lines, is refused once variants have offers or orders (Odoo would archive/merge the offered variants); adding values to an existing option works. A single-variant product that already has an offer cannot get variant options later (create a new product).
- A template with variants but no offers yet (between the two steps) is an offerless draft template; `_leaders_vendor_owns_content` still says False for it, so a new method `_leaders_vendor_owns_template` (also True with no offers) guards the variants routes.
- B2's bulk import still creates one variant per product (unchanged).
- Max 100 variants per product; specs max 50 lines / 4000 chars, plain text (escaped when rendered). Specs are translatable but the portal edits only the user's current language.
- Discount in the variants table is percent only (sale-price discounts through the offer edit page).
- FBL: stock cannot be given at creation (refused); FBL disabled => refused via A0 helper.
- Extra images are per template (shared by all variants), as in website_sale.

## DECISIONS
- Two-step flow (options first, offers second) avoids JS; the table reuses `_leaders_create_variant_offers` (validation of SKU uniqueness in batch and vs DB, tier limit counting one per offer, FBL helper, `_leaders_set_fbm_stock`, `_leaders_set_discount`).
- Specs as a Text field rendered by QWeb (escaped, no Html sanitising needed).
- Everything writes with sudo after ownership checks; attributes read via sudo (portal has no ACL on them).
