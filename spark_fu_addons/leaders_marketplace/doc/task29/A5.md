# A5 - Vendor terms acceptance

## STATUS
Done.

## FILES

## SETTINGS
None. With no active terms record nothing is checked (the spec's own guard), so default behaviour is unchanged; the feature switches on only when a manager creates/activates a terms version.

## MODELS_FIELDS_MIGRATIONS
- terms: `contract_ids`, `signed_count` (computed); create/write auto-deactivates other active versions (before saving), plus `_check_single_active` constraint as backstop. Helpers `_active_terms()`, `_pending_for(vendor)`, `action_accept(vendor, user, ip)`.
- contract: `terms_version` (related stored), `user_id`, `accepted`; constraint one signed contract per vendor+terms; `action_sign` (drawn signature) still needs a signature, now also stores user and attaches the document; `_sign_by_acceptance(user, ip)`; `_attach_pdf()` renders report `action_report_vendor_contract` into ir.attachment (pdf_id). Without wkhtmltopdf (and in tests) Odoo returns HTML: stored as .html; any render failure only posts a chatter note and never blocks signing.
- Migration post-A5: if several terms were active, only the highest version stays active.
- ACL: manager full on both (existing); reviewer/finance read on terms and contracts. No portal ACL (routes use sudo).

## ROUTES_API
- GET /my/vendor/terms: terms body + accept checkbox (owner), read-only for staff, reachable for approved and frozen vendors.
- POST /my/vendor/terms/accept (csrf, owner only; field `accept=1`): creates the signed contract (user, IP, version, attachment), redirects to /my/vendor. Missing tick: page re-rendered with error.
- Every route using `_require_vendor()` (all vendor portal pages/posts): owner -> 303 to /my/vendor/terms; staff -> 403 HTML notice page (no redirect loop). `check_terms=False` param used only by the terms routes. Logout is a core route and is untouched.
- API: /api/v1/vendor/dashboard and /orders return 403 `{"error":"terms_not_accepted","terms_version":N,"accept_url":"/my/vendor/terms"}` while pending.
- /vendor/apply still shows the latest active terms.

## UAT
1. Manager: Marketplace > Configuration > Vendor Terms > New (name, version, body). Activating it archives the previous active one.
2. Vendor owner opens /my/vendor (or any vendor page): redirected to /my/vendor/terms; tick and Accept: dashboard opens.
3. Vendor staff meanwhile sees the "waiting for acceptance" notice.
4. Marketplace > Operations > Vendor Contracts: signed row with user, IP, terms version, document attachment.
5. Create version 2: owner must accept again.

## LIMITATIONS
- Orders in flight are blocked for the vendor until the owner accepts (also staff). Customer pages, /seller pages and public catalog unaffected.
- Acceptance is per vendor (commercial partner), not per user.
- The contract document is HTML when wkhtmltopdf is missing.
- Vendor terms link is not in the nav; the owner is redirected to it.

## DECISIONS
- Frozen vendors must also accept (one click, terms page reachable) so the rule has no loophole; documented rather than exempting shipping pages.
- Auto-deactivation on activation plus a constraint (both) for "one active".
- Central enforcement by raising an HTTPException carrying a redirect/403 response from `_require_vendor` so none of the ~40 routes changed.
- API check added only to the two bearer vendor routes (public catalog route untouched).
