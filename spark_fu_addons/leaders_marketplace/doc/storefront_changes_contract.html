Breaking changes (act before this version goes live)

  1. Equipment leaves the cart. /cart/items and /orders refuse power and equipment products; use POST /equipment-requests.
  2. Registration sends an email code. /auth/register answers 202 and the session opens at /auth/register/verify; /auth/login can answer 403 email_not_verified.
  3. Google sign-up needs the phone for a new account (422 phone_required).

Everything else is additive (new endpoints, optional keys, optional parameters) or changes only which products are returned.

Feature 1 — Registration and authentication

Breaking POST /auth/register

Based on: project guide (spark fu guid.md), Feature 1: Registration, authentication and account — Two ways to sign in: Google, or email + password with an OTP code that proves the email before the account opens

With the email code on (the default), registering no longer opens a session: it sends a 6-digit code to the email and answers 202. The session opens at /auth/register/verify. Registering again with the same email before confirming sends a new code (not email_taken). Setting leaders_marketplace.auth_register_otp = 0 in Odoo restores the old behaviour.

Request

{"name": "Mona Adel", "email": "mona@example.com", "phone": "+201001234567", "password": "Secret123"}

Response

202
{"verification": "email", "email": "mona@example.com", "expiresIn": 600}
StatuscodeWhen
422validation_errorname / email / phone / password invalid
409email_takena confirmed account has this email
409phone_takenthe phone belongs to another account

New POST /auth/register/resend

Based on: project guide (spark fu guid.md), Feature 1: Registration, authentication and account — OTP at sign-up — limit on resends

Sends the sign-up code again. Always 202, whether the account exists or not. Limited to 3 per email every 10 minutes.

Based on: project guide (spark fu guid.md), Feature 1: Registration, authentication and account — OTP at sign-up

An account that never entered its sign-up code cannot sign in: a fresh code is emailed and the answer is 403 email_not_verified. Show the code screen.

The first Google sign-in (account creation) now needs the phone. Without it the answer is 422 phone_required; ask the phone and call again with it. Existing accounts sign in without it.

Feature 4 — Equipment (buy and rent)

Breaking POST /cart/items, PATCH /cart/items/<id>, POST /orders

Based on: project guide (spark fu guid.md), Feature 4: Equipment (buy and rent) — Equipment is not added to the cart: three request paths

Equipment (power and equipment shelves), bought or rented, priced or not, is refused by the cart and the checkout. Spare parts keep the cart.

StatuscodeWhen
409equipment_request_onlycart: an equipment product
422validation_error/orders: items.N is an equipment product

New POST /equipment-requests

Based on: project guide (spark fu guid.md), Feature 4: Equipment (buy and rent) — Three request paths + rent in the platform's name

Bearer required. One endpoint for equipment:
• priced, no services → kind: purchase, status: requested, nothing to pay;
• priced, with services → requested; the admin prices the services, the request becomes awaitingPayment with paymentUrl; paying confirms it;
• no price → kind: quote;
• rent → a booking (kind: rent); only the delivery is paid at booking when asked.
services must be among the product's services (see the product object).

Request

// buy
{"productId": "625", "listing": "buy", "quantity": 1, "offerId": "1050", "services": ["installation", "delivery"],
 "shipping": {"name": "Mona", "phone": "+201001234567", "governorate": "giza", "address": "6th of October"}, "note": ""}
// rent
{"productId": "625", "listing": "rent", "rentPeriod": "week", "rentUnits": 2, "startDate": "2026-12-01",
 "services": ["delivery"], "contractAccepted": true, "shipping": {...}}

Response

201
{"reference": "ER-0004", "kind": "rent", "status": "awaitingPayment", "productId": "625", "quantity": 1,
 "services": ["delivery"], "placedAt": "...", "unitPrice": 255000, "amountDue": 15000,
 "paymentUrl": "https://.../orders/SO-.../payment", "rental": {"from": "2026-12-01", "to": "2026-12-15", "pricePerDay": 255000}}
