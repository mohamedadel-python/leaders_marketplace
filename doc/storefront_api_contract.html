The landing page needs only two of these: GET /categories and GET /products (featured, or kind with limit, plus power and location for its search). The rest belong to the category, details, cart and account pages.

Conventions

  • JSON in, JSON out. No envelope: a list body is { items, totalCount, page, pageSize } (landing mode: a plain array), a single resource is the resource itself.
  • camelCase names. Optional fields are omitted when unset, never null (the one exception: avatar).
  • Money is an integer in minor units (piastres): price: 185000000 is 1,850,000.00 EGP. The frontend formats it. Filter bounds are whole units (priceMin=1000000).
  • Dates are ISO 8601 in UTC (2026-10-29T14:47:40Z).
  • Array query params are comma-joined: ?condition=new,used&brand=Perkins,Cummins.
  • Paging is page-based: page (1-based) and pageSize (default 8, max 48). totalCount is the whole filtered set.
  • The catalog endpoints are public. Cart endpoints accept a Bearer when present. Profile endpoints require one.
  • Protected endpoints read Authorization: Bearer <accessToken>. Missing, expired, forged or malformed is 401 session_expired: refresh once and retry.
  • Send every request with credentials: "include" (the guest cart and the refresh cookie). CORS answers with the exact configured origin, never *, and allows GET, POST, PUT, PATCH, DELETE, OPTIONS with Authorization, Content-Type. Allowed origins today: http://localhost:3000 and https://spark-fu.com, on every route; the response carries Vary: Origin and Access-Control-Allow-Credentials: true. The refresh_token cookie is Secure; HttpOnly; SameSite=None (the API and the site are different sites), and so are the lines that clear it.
  • Language: send Accept-Language: ar (or en) on every call. With ar, names and titles (product, category, order, quote and line names, specs.partType) come in Arabic where Odoo has a translation, and fall back to the source text otherwise. The same header sets the locale of paymentUrl and its return page.
  • Services: POST /quotes takes service in inspection | maintenance | solar | load-bank | temporary-power. /categories lists tiles for maintenance, inspection and solar only; load-bank and temporary-power are services with no tile.
  • Rate limit: 120 requests per minute per IP on each group (catalog, cart, account). Over it is 429 rate_limited. The frontend server's IP (it renders the landing and details pages for every visitor) is exempt: the admin lists it in the system parameter leaders_marketplace.storefront_rate_limit_exempt_ips.

Errors are a non-2xx status with { "code": "snake_case", "message": "…" }; validation adds fields keyed by request field, exactly as in the auth contract.

The catalogue's shape

Three shelves (kind) with three sub-categories each, plus the services group. The structure is compiled into the frontend; products carry exactly these slugs. Categories are managed in Odoo: each tile carries its name (in the language of Accept-Language), an optional description, a picture (image) and an icon. /categories is sent with Cache-Control: public, max-age=300.

Product object

One shape for every product endpoint, in lists and alone. The card and the details page read the same object.

type Money = number;                       // integer minor units (piastres): 185000000 = 1,850,000.00 EGP
type ProductKind = "power" | "equipment" | "part";
type ListingType = "buy" | "rent";
type ProductCondition = "new" | "used" | "refurbished";
type PartOrigin = "original" | "aftermarket";
type PartSource = string;                  // the admin's list; today "turkish" | "chinese" | "egyptian"
type PowerSource = string;                 // the admin's list; today "diesel" | "electric" | "petrol" | "gas" | "hybrid"

interface Product {
  id: string;
  slug: string;                  // URL segment, unique, stable
  brand: string;                 // "Perkins"
  model: string;                 // equipment: "1506A-E88TAG5"; parts: the part number
  kind: ProductKind;
  subcategory: string;           // slug from the table above
  listing: ListingType;          // the default way it is offered
  availableFor?: ListingType[];  // present only when it differs from [listing]
  inspected: boolean;            // the "inspected" badge
  image?: string;                // absolute URL, main photo
  gallery?: string[];            // absolute URLs, main photo first
  rentPrice?: Money;             // per day, minor units; present when it can be rented and the admin set a rate; absent => "request a quote" for the rental
  price?: Money;                 // present => "add to cart"; absent => "request a quote"
  inStock?: false;               // sent only when the admin flagged it out of stock
  sku?: string;                  // part number, else the internal reference; omitted when neither exists
  sources?: PartSource[];        // parts: sources it can be ordered in
  listedAt: string;              // ISO 8601 UTC; what "newest" sorts by
  specs: ProductSpecs;
}

interface ProductSpecs {         // every key is omitted when unset
  power?: string;                // "250 kVA" | "3 ton" | "500 A" ...: capacity with its unit
  kva?: number;                  // rating for the kVA filter; set when the unit is kVA or kW
  primePower?: string;           // "225 kVA"
  engine?: string;               // "Perkins 1506A"
  engineSize?: string;           // "8.8 L"
  powerSource?: PowerSource;
  runningHours?: string;         // "6,400"
  condition?: ProductCondition;
  location?: string;             // city key: "cairo" | "giza" | "alexandria" ...
  partType?: string;             // parts: first tag
  compatibility?: string;        // parts: "Perkins 1506A-E88TAG5, FG Wilson P100-5"
  origin?: PartOrigin;           // parts: "original" when the source is the maker's own, else "aftermarket"
  dimensions?: string;           // read from the product's specs text ("dimensions: 93 x 178 mm")
  thread?: string;               // same ("thread: M20 x 1.5")
  changeInterval?: string;       // same ("change interval: every 500 h")
  warranty?: string;             // "12 months"
}

Rules the UI depends on. price decides the card: priced products show "add to cart"; products without it show "request a quote". condition, origin, powerSource, location and the source codes are keys the UI translates; the other specs are display strings. For the numeric filters the backend uses specs.kva, specs.engineSize and specs.runningHours.

GET/productsCategory page, sub-category page, landing rowsno auth

One endpoint, two modes. Listing mode (the category and sub-category pages) returns Page<Product>. Landing mode (featured or limit present) returns a plain Product[]. Only published products appear. Every list item is the full Product; no second call per card.

Cart

A signed-in customer's cart is keyed by their user. A guest's cart is keyed by the spark_cart cookie (HttpOnly; Secure; SameSite=None; Path=/, 30 days), set on the first write. The server computes lineId from the product and the options that change the ask, so the same generator bought and hired are two lines. A cart's lines show the full Product, so the cart page makes no extra call.

Prices: a buy line's unitPrice is the product's price; a rent line's is the daily rent × 1 (day), 7 (week), 30 (month). A custom rent line (a term agreed with us) has no unitPrice: it goes to the quote tab, and POST /orders refuses it with the quote-only 422. A line without a price has no unitPrice and adds nothing to subtotal.

Flows end to end

Landing

  1. GET /categories for the explorer tiles.
  2. GET /products?featured=true&limit=8 for the featured row.
  3. One GET /products?kind=…&limit=50 per shelf.

Category page (/power-solutions)

  1. GET /products?kind=power&page=1&pageSize=9.
  2. GET /products/facets?kind=power for the sidebar.
  3. Every sidebar change re-queries the list with the filter params.

Sub-category page

  1. Same two calls with subcategory=generators, page size 6.

Product details

  1. GET /products/:slug.
  2. …/related and …/bought-together for the shelves.

Add to cart, then sign in

  1. POST /cart/items with the order panel's options (a guest gets the cookie).
  2. After login, POST /cart/merge with the Bearer.
  3. Lines with a price go to checkout (a sale with price, or a hire with rentPrice); the rest go to POST /quotes.

Checkout

  1. GET /delivery/regions for the governorate and city lists and the delivery fee; optionally GET /promo-codes/:code.
  2. POST /orders with the lines, shipping and payment method. 409 price_changed: show the new price and ask again.
  3. Card or wallet: follow paymentUrl; it returns to /<locale>/orders/<reference>/confirmed. Cash on delivery: go straight to the confirmation page.
  4. GET /orders/:reference for the status page; POST …/cancel while placed or preparing.

Quote or service request

  1. POST /quotes (a guest may send one; a signed-in user finds it in GET /account/orders?kind=quote or kind=service).
  2. GET /quotes/:reference for its status; POST …/cancel to withdraw it.

Account

  1. After login, GET /account/profile for the header and the profile page.
  2. Orders page: GET /account/orders?kind=purchase, switching kind per tab.

Notes and open points

  • Lists the admin manages. Brands, spare-part tags, equipment models, sources and energy sources are managed in Odoo (Marketplace, Configuration). A new source or energy source appears in sources, powerSource and the filters without a deployment, so the UI should not hard-code those lists; it should translate the codes it knows and show the raw code for a new one.
  • powerSource is not limited to diesel | electric. Petrol, gas and hybrid products send their own code. Tell backend if the UI should only ever receive two values.
  • model of a part is its part number, since parts have no model.
  • sku is the part number, else the internal reference. It is omitted when neither exists: the serial number is never used.
  • kva is set for products rated in kVA or kW (a kW rating is counted as the same number, which understates generators and load banks: 100 kW is about 125 kVA at 0.8 power factor. Where the admin can enter kVA, kVA is preferred). Welders (amps), forklifts (tons) and loaders (m³) have no kva; their rating is in specs.power.
  • Stock. The platform does not track quantities. inStock: false appears only when the admin flags a product, and then adding it to a cart is 409 out_of_stock.
  • Order references. Purchases are numbered SF-1043…; quote requests SQ-…; service requests SV-….
  • Password change. The refresh cookie is scoped to /auth, so /account/password cannot tell which device is current; it revokes all refresh tokens and sets a fresh one for the calling device.
  • Listings. listing=buy never returns a product from a rent-only category (availableFor: ["rent"]); listing=rent returns only rentable products.
  • Admin-managed data for checkout. Promo codes (Marketplace, Promo Codes), the delivery fee, lead days and city keys of each governorate (the platform delivery prices). A governorate without a platform delivery price cannot be ordered to.
  • Payment. paymentUrl is the platform's payment step; the gateway behind it is the backend's choice, and the frontend only follows the URL.
  • Staging fixtures. The demo server holds 28 products across the nine sub-categories and the user demo@spark-fu.example / Secret123 (phone +201001234567, company "Spark Demo Contracting", city cairo), with one purchase and four quote/service requests.
