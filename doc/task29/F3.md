## STATUS

## ROOT_CAUSE
DNS was checked with getaddrinfo and then requests.get resolved again (rebinding window); redirects were re-checked manually but each hop still had the double resolution; any port was allowed; downloads were on by default.

## FIX
safe_get(url, timeout, max_bytes, allowed_schemes): strict URL parse (no userinfo, no whitespace/control chars/backslash, <=2048 chars, only default ports 80/443), ONE getaddrinfo, all answers must be public (private/loopback/link-local/multicast/reserved/unspecified, IPv4-mapped/6to4/teredo/NAT64 unwrapped or rejected, plus is_global), connect with urllib3 to the resolved IP with Host header = original host; https: server_hostname + assert_hostname = original host, CERT_REQUIRED. No redirects (3xx = warning). Streamed body with hard byte cap, Content-Length pre-check, overall deadline (checked between chunks; a single blocked read is bounded by the per-socket timeout). Errors are SafeFetchError(code) mapped to translated row warnings in the model. Mime check (guess_mimetype) stays in the model.

## SETTINGS
leaders_marketplace.vendor_import_allow_image_urls (Boolean, default False, missing = off; shown under Vendor Bulk Import, visible when import is on). Off: image_url ignored with a row warning at validation and at apply; no DNS/network at all; product created without image. BEHAVIOUR CHANGE vs B2 (downloads were on): documented in CHANGES. No migration.

## LIMITATIONS
- https path verified with real urllib3 pool objects and their connection attributes, not with a live TLS handshake against a local TLS server (no test cert infra).
- Only ports 80/443 (deliberate); images on custom ports are refused.
- Deadline is checked between chunks; one blocked recv can take up to the per-read timeout beyond it.
- Uses the first resolved address only (no fallback to other answers).
- Proxies from environment variables are not used (direct connection).
