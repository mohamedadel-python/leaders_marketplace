# F2 - Cancelled remainder of a partial shipment adjusts money
STATUS: done.
FILES: models/sale.py (qty_cancelled/qty_kept, _compute_amounts on kept qty, VendorOrder._leaders_cancel_quantities, action_cancel_quantities, group.action_cancel_remaining/_leaders_open_quantities, _net_qty_sold), models/stock.py (picking.action_cancel hook), models/accounting.py (post_quantity_cancellation_entry, create_cancellation_refund_payment_partial), models/vendor_invoice.py (_create_credit_note_for_cancellation), models/account_payment.py (leaders_cancel_refund_move_id), models/settlement.py (wallet type cancelled_qty + sales-base tuples), models/commission.py (achievement metrics on kept qty), models/returns.py (return line ratio on kept qty), models/unified_orders.py, views/vendor_order_views.xml, controllers/vendor_api.py (qty_cancelled in JSON), tests/test_cancel_remaining_money.py, README.md, CHANGES_v4.md.
ROOT_CAUSE: A6 cancel remaining only cancelled the picking; amounts, invoice, escrow, earning and commission still used the ordered quantity.
FIX: one method `VendorOrder._leaders_cancel_quantities(lines_qty, reason, by)` (by = vendor/warehouse/customer/platform) used by group.action_cancel_remaining (vendor, portal/back office), by stock.picking.action_cancel (a cancelled picking of a group that already has a done picking -> by warehouse) and by back-office `action_cancel_quantities` (manager group; platform/support, also for a customer request). Customer portal stays closed (A2 rule).
Entries: online, earning not created: Dr escrow (partner vendor) / Cr customer receivable for the cancelled amount (reconciled with the open collection when unpaid, else draft outbound refund payment linked by payment.leaders_cancel_refund_move_id, reconciled on post). Earning later uses reduced vendor_net so escrow ends 0. Earning already created: escrow of the part is gone, so Dr vendor payable (net drop) + Dr commission income (rest) / Cr receivable (mirror of a return after release) plus negative wallet tx `cancelled_qty` carrying that move (payable = wallet). COD: no entries; FBL collection is booked later on the kept amount; FBM confirmed cod_collected gets a negative cod_collected tx. Credit note: vendor invoice out_refund `<code>/RINV/<year>/<seq>` reversed_invoice_id = invoice, no return_id; payment_state paid when nothing to send back.
DECISIONS: product_uom_qty stays the ordered qty, amounts use ordered-cancelled; return refund ratio, achievement metrics and _net_qty_sold use the kept qty. New wallet type cancelled_qty counted in commission sales base (settlement tuples). Second cancel of the same qty raises UserError (nothing changes). Cancelling everything with nothing shipped is refused (normal cancel). No migration (default 0). "Earning already exists" is unreachable through normal on_ship flow (earning needs all groups fully shipped); tested by creating the earning early (back-office).
TESTS: tests/test_cancel_remaining_money.py (17 tests: online paid/unpaid, COD FBM/FBL, earning before/after, ledger escrow 0 & payable == wallet unsettled, receivable 0, commission plan amount_sold, idempotency, warehouse hook, ACL). Full suite: 926 tests 0 failed. A6 tests unchanged (none asserted unchanged amounts).
LIMITATIONS: tier returns reserve not resized; legacy per-order commission lines / cod_due entry not resized; COD order with an already booked collection entry is refused; per-cancel credit note (several partial cancels make several notes); no customer notification.
