## ROUTES_API
Auth: `Authorization: Bearer lmk_<8hex>_<secret>`; read keys can only GET (403 insufficient_scope).
- GET /api/v1/vendor/offers (filters state, fulfillment_type, seller_sku; page, limit<=100) -> {page,limit,total,next,items}
- GET/PATCH /api/v1/vendor/offers/<id>: PATCH {"price":120,"discount":{"type":"percent","percent":15,"start":..,"end":..}|null,"stock":10,"submit":true}
- GET /api/v1/vendor/orders (state, updated_since), GET .../orders/<id>
- POST .../orders/<id>/ship {"tracking_ref":"T1","group_id":?,"carrier_id":?,"lines":[{"line_id":1,"quantity":2}]} or {"groups":[...]} (FulfillmentGroup.action_ship)
- POST .../orders/<id>/delivered {"group_id"?} (action_report_delivery; customer_confirm mode respected)
- GET /api/v1/vendor/returns, /returns/<id>; POST .../returns/<id>/decision {"decision":"approve|reject","note":".."}
- GET /api/v1/vendor/wallet (balances + paginated transactions), GET /api/v1/vendor/settlements
- GET /api/v1/openapi.json (OpenAPI 3.0.3 from a Python dict)
- Portal: GET /my/vendor/api, POST /my/vendor/api/keys, POST /my/vendor/api/keys/<id>/revoke (owner only).
Errors: {"error","message","details":[{field,message}]}; 401/403/404/422 (business errors and Idempotency conflict)/429. Idempotency-Key on POST/PATCH: replay returns stored response with `Idempotent-Replay: true`; retention 24h (hourly cron).

## UAT
1. Settings > Marketplace: enable Vendor Write API. 2. Vendor owner > API > create a "Read and write" key, copy it (shown once). 3. curl the endpoints above; revoke the key on the page and see 401. 4. Disable the switch: page and endpoints 404.

## LIMITATIONS
Frozen vendors can read but not PATCH offers; FBL shipping is refused (handled by the platform). Rate counters are per minute window (fixed window).

## DECISIONS
Own key model (scope, revoke, last used) instead of native keys; unchanged behaviour for native-key calls on the legacy orders route; stock/price/discount reuse portal model methods; price change sends offer back to draft like the portal edit.
