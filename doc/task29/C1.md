## UAT
1. Customer opens /my: sees My orders, Returns & disputes, Account details, Connection & Security (+ Wishlist if website_sale_wishlist installed); no Quotations/Orders/Invoices until documents exist. Set the setting to Always/Never and reload.
2. Vendor owner opens any /my/vendor page: breadcrumbs Home > Vendor > Section > Detail, sidebar (top scrolling bar on mobile) with Dashboard, Products, [Import], Orders, Returns, Disputes, Performance, Finance, Delivery Zones, Staff, [API], Profile, and "My purchases" (-> /my/marketplace/orders). Staff sees no owner-only entries. Import / API appear only when their switches are on.
3. Owner with unsigned terms: sidebar entries are greyed out (not links) on /my/vendor/terms.
## LIMITATIONS
Pages keep their inner `container`; CSS neutralises it inside the layout (C2 restyles). Detail breadcrumb labels are generic ("Order details" ...) from `_DETAIL_LABELS` in models/portal_nav.py. Vendor home page /my keeps its card design. Counter alert cards (Quotations to review) are revealed by the standard counters JS, not server side.
## DECISIONS
Nav/breadcrumb data live in ONE model (`leaders.portal.nav._vendor_nav(path)`), called from the layout, so every vendor render path (also request.render in _raise_terms_required and controllers outside portal.py) gets the same context; no controller change needed. All vendor templates now `t-call leaders_marketplace.portal_vendor_layout` (ids unchanged; the per-page `portal_vendor_nav` call was removed; `portal_vendor_nav` is now the sidebar component, and still works standalone). To add D3 Questions: set route_exists True (remove the False) in `_vendor_entries`. To add a customer card: add an entry to `_customer_entries`. Import entry visible to staff too (route only needs _require_vendor); Finance/Zones/Staff/API/Profile owner-only as before.
