Services API contract: service pages and service requests

What the services pages (/services and /services/:slug) call: the list of services, one service page with its checklist, and the request form, which sends POST /quotes. Every response below was captured from the running backend. The Try it tabs call a live server: set the base URL and the language in the bar above.

Implemented by backend · live on odooapp.mdarj.org · updated 2026-11-03

Companion to the storefront contract (catalog, cart, checkout, quotes) and the auth contract. Nothing in those two changed in a breaking way: the endpoints below are new, and POST /quotes and GET /quotes/:reference gained stricter checks and one field for service requests only.

Conventions

  • Same as the storefront contract: JSON, no envelope, camelCase, optional fields are omitted when unset (never null), errors are { code, message, fields? }.
  • Language. Send Accept-Language: ar or en. Every text of a service (name, summary, lead, titles, checklist, deliverables) comes in that language. A text without a translation falls back to the source text (English), never an empty string. The error messages of POST /quotes follow the same header.
  • Cache: off during development. While the system parameter leaders_marketplace.api_no_cache is 1 (it is now), GET /services, GET /services/:slug, the icon and /categories answer Cache-Control: no-store, so an edit in Odoo shows in the very next response. At launch the backend sets it to 0, with no code change, and they go back to public, max-age=300. Odoo keeps no other copy of these answers; a proxy cache in front of Odoo (nginx proxy_cache, a CDN) is a server setting to check on each host.
  • Order. The list is in the order the admin sets (drag and drop in Odoo). The frontend shows it as it comes, it does not sort.
  • Only published services are listed. An unpublished or unknown slug is 404 not_found: show the 404 page.
  • The slug never changes once a request uses it (Odoo refuses the edit), so links and old requests keep working.
  • No price. A service has no price in the API; the team quotes it after the request.
  • CORS is the storefront's: exact origin, credentials: "include", GET, POST, OPTIONS are allowed. The origins come from the Odoo system parameter leaders_marketplace.auth_cors_origin; https://new.spark-fu.com must be in it on each server.
  • Rate limit. /services uses the catalog group, POST /quotes the quotes group (120 per minute per IP each, 429 rate_limited over it). Two system parameters change it without a deployment: leaders_marketplace.storefront_rate_limit raises the per-minute limit (a value below 120 is ignored), and leaders_marketplace.storefront_rate_limit_exempt_ips lists IPs that are never limited, comma separated (the build server stays on it after launch). Behind a proxy, Odoo must run with proxy_mode so it sees the caller's IP and not the proxy's.

Service object

interface ServiceSummary {            // one item of GET /services
  id: string;                         // "7"
  slug: string;                       // "inspection": the page URL /services/inspection, and the value of POST /quotes service
  name: string;                       // card title, page <h1>, footer link
  summary: string;                    // one sentence for the card
  icon?: string;                      // absolute URL, always /services/:slug/icon; omitted when there is no icon
  mandatoryOnPurchase: boolean;       // true: show the "required on purchase" badge
  requestTitle?: string;              // title of the request form; omitted when the admin left it empty
  coverageGovernorates?: number;      // how many governorates the service reaches; omitted when not set
}

interface Service extends ServiceSummary {   // GET /services/:slug
  lead: string;                       // hero paragraph; also the page's meta description
  panelTitle: string;                 // title of the request panel
  requestTitle: string;               // title of the request form
  checklistTitle: string;             // "What exactly do we inspect?"
  checklistLead: string;              // line under the checklist title
  checklist: string[];                // in the admin's order; may be empty
  deliverable: string;                // fact in the request panel ("Written inspection report")
  deliverableShort: string;           // bullet in the hero ("Written report")
}
On GET /services/:slug the text fields of the page are always sent (an empty string when the admin left one empty), so the page can render without checks. Only icon and coverageGovernorates are optional there.

Service requests

The form on a service page sends POST /quotes with service set and items: []. A guest may send one. With a valid Bearer the request is linked to the user and appears under GET /account/orders?kind=service. An invalid Bearer is ignored, never 401. References are SV-…. A quote request of products (no service) keeps the rules of the storefront contract, unchanged.

POST/quotesSend a service requestno auth; Bearer optional

Every field is checked, and every problem is reported in one answer: fields has a message for each wrong field, keyed by its path (name, serviceDetails.neededBy). The messages are in the language of Accept-Language, so they can be shown as they are under each input. Nothing is saved when the answer is 422. An empty string is the same as a missing field: the form can send its inputs as they are.

Managed in Odoo

Marketplace › Operations › Service Pages (marketplace managers). Each service is an Odoo product of type Service, kept out of the shop and out of /products. The admin edits, per service:

  • name, slug, published, required on purchase, governorates covered, icon, the landing tile it belongs to, and the order (drag and drop);
  • the page texts (summary, lead, panel and form titles, deliverables) and the checklist lines, in English and Arabic;
  • Service responsible: the user who gets a to-do in Odoo for every new request of that service.

The requests themselves are in the customer requests list, with the service linked on each one.

Decisions and open points

  • Mandatory inspection (Part 4): option B, offline. mandatoryOnPurchase only shows the badge and the rule on the page. A purchase is not blocked and no inspection fee is added at checkout; the team arranges the inspection after the order. Tell backend if option A (fee and refund in checkout) is wanted: it is a separate piece of work.
  • Phone format: on. A service request needs an international phone (+20…); otherwise fields.phone is Enter the phone in international format, e.g. +201001234567. The switch is the system parameter leaders_marketplace.storefront_service_phone_e164 (1).
  • Team notification: a to-do for the service responsible in Odoo.
  • Customer confirmation: done. When serviceDetails.email is set, the customer gets an email with the reference (SV-…), the service name and the phone the team will call, in the language of locale (else Accept-Language). No email in the form, no email sent. The answer of POST /quotes never waits for or fails because of the email.
  • Coverage number: done. coverageGovernorates on each service, set by the admin per service. It is omitted when the admin has not set it: then use the number of governorates of GET /delivery/regions.
  • Guest requests: done. At sign-up and at every sign-in, requests sent as a guest join the account when both the request's email (serviceDetails.email) and its phone equal the account's email and phone. One alone is not enough, because neither is verified at sign-up and a stranger could otherwise read someone's request. A guest request without an email is never attached. The frontend can show the track link to a guest who then signs in.
  • Texts. The inspection texts are the ones from the frontend. The other four services still have the texts written by backend: the admin replaces them under Marketplace › Operations › Service Pages once the company confirms the wording.
  • Icons. load-bank and temporary-power now have their own icons, so every service sends icon.

How to verify

Pages

  1. GET /services with ar then en: five services, same order, translated names.
  2. GET /services/inspection: eight checklist lines.
  3. GET /services/nope: 404 not_found.
  4. Headers: curl -s -D - -o /dev/null https://odooapp.mdarj.org/services | grep -i cache-control prints Cache-Control: no-store; the same for /services/inspection and /categories.

Request

  1. Send the Try it body of POST /quotes with ar: 422 with name, serviceDetails.neededBy and serviceDetails.equipmentType, in Arabic.
  2. Fix the three fields: 201 with SV-….
  3. Signed in: it is in GET /account/orders?kind=service, and GET /quotes/SV-… has serviceName.
  4. As a guest, send a request with an email, then sign up with the same email and phone: GET /quotes/SV-… answers 200.
